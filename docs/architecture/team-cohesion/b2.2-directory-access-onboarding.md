### B2.2c — Onboarding + cycle break

**Cycle today**

```
onboardingInvitation.server.ts
  → createOnboardingPinSetupToken (onboardingPinLayer.server)

onboardingPinLayer.server.ts
  → acceptOnboardingInvitation (onboardingInvitation.server)
```

**Break (one-way leaves, B2.1a style)**

1. `onboardingPinSetup.server.ts` — `createOnboardingPinSetupToken`, `loadPinSetupByToken` (no invitation imports)
2. `onboardingInvitationAccept.server.ts` — `acceptOnboardingInvitation` (no PIN imports)
3. `onboardingInvitation.server.ts` — send/resend/load; imports pin-setup leaf only
4. `onboardingPinLayer.server.ts` — complete/load status; imports invitation-accept leaf only

DAG: `invitation → pinSetup`, `pinLayer → invitationAccept` → **`cycleCount: 0`**.

Shared token hashing may continue to import access invite-token helpers acyclically — **not** a semantic merge with login invites.

**Also move:** `onboardingTypes`, centre core, invite URL core, staff-create core/server, checklist, page loader (+ tests).

**Add** `team/onboarding/server.ts`.
