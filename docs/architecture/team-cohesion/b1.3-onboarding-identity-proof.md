**Status:** GREEN (2026-08-05)

## What landed

Canonical Onboarding Centre loader (`src/lib/workforce/onboarding/onboardingPage.server.ts`) now consumes:

```ts
resolveStaffIdentities({ tenantId, by: "staffMemberId", staffMemberIds })
```

and projects via `@/src/lib/team/onboarding`:

- `StaffOnboardingEntry` (presentation DTO — not the full `StaffIdentity`)
- Distinct `onboardingStatus` vs `loginAccessStatus`
- `attentionReasons` for incomplete / ambiguous / invalid links and onboarding↔login divergence
- Action flags bridged onto legacy `OnboardingStaffRow` for the existing UI

Onboarding continues to own invite semantics, checklist state, expiry/resend/cancel rules, and staff-creation orchestration. Dual-table writes for linked staff creation live in `staffTenantLinkRepair.server.ts` (`provisionOnboardingStaffPair` / `rollbackOnboardingStaffPair`) — the explicit repair / provision boundary.

## Behavioural rule

Lifecycle-only identities are **first-class onboarding states**, not filtered out. They surface:

- `scheduling_record_missing`
- `identity_link_incomplete`
- and `canCreateSchedulingRecord` when the target is otherwise safe

Ambiguous / cross-tenant / invalid targets:

- show reconciliation / mismatch / invalid attention
- suppress send / resend / copy UI flags
- server send/resend mutations reject with a reconciliation error before mutating invites

Onboarding invite and login access remain separate:

- completed onboarding + login not started → `login_access_outstanding`
- login active + onboarding incomplete → `login_active_onboarding_incomplete`
- completing onboarding never activates login access

## Deferred product clarification (do not solve accidentally)

B1.3 clarifies the deferred **B1.1.1** directory question. Lifecycle-only people fall into at least:

1. legitimate onboarding-in-progress
2. incomplete linkage requiring repair
3. stale / duplicate lifecycle records

Eventual directory behaviour should probably be:

- active / schedulable people in the default directory
- lifecycle-only onboarding records in Onboarding
- ambiguous / stale records in Reconciliation
- optional all-identities admin filter

Do **not** add every lifecycle-only record to the main directory indiscriminately.

## Performance
