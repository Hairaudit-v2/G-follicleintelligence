## Behaviour change (intentional)

`assertStaffAppointmentWithinWorkingHours` now loads overlapping `fi_staff_availability_blocks` and uses roster effective availability:

- Active leave/sick/unavailable/… **denies** booking
- Active `available_override` **allows** outside weekly hours (and empty weekly when override present)
- Weekly-only empty hours / outside-hours deny paths preserved when no override

Same-day overrides via existing `createAvailabilityBlock({ blockType: "available_override" })` now affect booking acceptance. Command Centre “available outside hours” UI remains deferred.
