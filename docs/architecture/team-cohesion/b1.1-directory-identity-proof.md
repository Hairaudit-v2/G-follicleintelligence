# FI-TEAM-COHESION-B1.1 — Directory Identity Proof

**Status:** GREEN (2026-08-05)  
**Predecessor:** [b1-identity-foundation.md](./b1-identity-foundation.md)

## What landed

Canonical directory loader (`src/lib/staff/staffDirectoryLoader.server.ts`) now consumes:

```ts
resolveStaffIdentities({ tenantId, by: "staffId", staffIds })
```

and projects via `@/src/lib/team/directory`:

- `StaffDirectoryEntry` (presentation DTO — not the full `StaffIdentity`)
- `attentionReasons` for incomplete / ambiguous / invalid links
- Legacy `staffLifecycleByStaffId` derived from identity (enrich path unchanged for valid linked staff)

Directory continues to own search, filters, sorting, and attention labels.

## Behavioural rule

Partial / invalid identities are **not** hidden. Scheduling staff without a lifecycle projection remain visible with:

- `lifecycle_record_missing`
- `identity_link_incomplete`

Ambiguous links show `identity_requires_reconciliation`. Cross-tenant / invalid surface explicit attention pills in the directory secondary view.

Lifecycle-only people without a scheduling row are **not** invented as new UI rows in B1.1 (annotate-only). Track as **B1.1.1** if product wants orphan lifecycle visibility.

## Performance

Identity resolution for the directory list uses a **fixed** data-access budget inside `resolveStaffIdentities` (bounded `.in(...)` loads for scheduling + lifecycle), not one operation per staff member.

Stable ordering: directory entries follow the scheduling staff list order; batch `byKey` preserves deduplicated input order.
