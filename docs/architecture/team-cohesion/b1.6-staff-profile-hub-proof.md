# FI-TEAM-COHESION-B1.6 — Staff Profile Hub

**Status:** GREEN (2026-08-05)  
**Predecessor:** [b1.5-compliance-identity-proof.md](./b1.5-compliance-identity-proof.md)

## What landed

Staff profile is now the canonical **person-level composition surface** under `src/lib/team/profile/`:

```
Resolve canonical StaffIdentity (discriminated by staffId | staffMemberId)
        ↓
Load domain facts (shared identity — no per-domain re-resolve)
        ├── directory  → projectStaffDirectoryEntry
        ├── access     → projectStaffAccessEntry
        ├── onboarding → projectStaffOnboardingEntry
        ├── roster     → projectRosterStaffEntry (null when no staffId)
        └── compliance → projectStaffComplianceEntry (lifecycle subjects)
        ↓
Compose StaffProfileHubModel (+ prioritised attentionReasons)
        ↓
Legacy overview adapter → StaffProfileOverviewModel (UI parity)
```

Legacy `src/lib/workforce/staffProfileHub.server.ts` is a **compatibility adapter** that delegates to `loadStaffProfileHubBundle` — it no longer resolves identity gates, readiness audits, or dual-table joins itself.

`StaffProfileActionMenu` consumes canonical domain action flags:

```tsx
<StaffProfileActionMenu
  accessActions={profile.access /* flags */}
  onboardingActions={profile.onboarding?.actions}
  complianceActions={profile.compliance?.actions}
  identityActions={profile.actions.identity}
/>
```

## Identity direction

```ts
loadStaffProfileHub({ tenantId, by: "staffId", staffId })
loadStaffProfileHub({ tenantId, by: "staffMemberId", staffMemberId })
```

No silent ID-type fallback inside the hub. The WorkforceOS route may still try lifecycle then scheduling loads explicitly at the page-loader boundary; once a lifecycle row is known, the hub is always invoked with `by: "staffMemberId"`.

## Partial identity behaviour

| Identity state | Profile behaviour |
|----------------|-------------------|
| Linked | Full sections |
| Scheduling-only | Profile available; lifecycle warning; no invented onboarding/compliance subject when no member id |
| Lifecycle-only | Onboarding / access / compliance available; **no** invented roster entry |
| Ambiguous | Read-only; unsafe domain actions suppressed |
| Invalid / cross-tenant | Hard rejection (`not_found` / `cross_tenant` / `invalid`) |
| Missing auth | Access attention retains `missing_auth_identity` |
| Terminated / suspended | Employment vs login access remain distinct via identity + access projections |

## Query budget

`loadStaffProfileHub` / `loadStaffProfileHubBundle`:

1. **One** `resolveStaffIdentity` (discriminated input)
2. Parallel fact loads with **shared** identity:
   - access centre row (`preresolvedIdentitiesByMemberId` — skips second resolve)
   - onboarding checklist + invite
   - credentials (when `staffMemberId` present)
   - optional gated scheduling presentation (leave + command-centre **labels** only)
3. In-memory projections + composition

No per-domain identity resolve loop. Command-centre intelligence remains a gated **label supplement** for overview parity (training / next-shift / score); access, onboarding, roster, and compliance **policy** come from domain projections.

## Safety preserved

| Concern | Disposition |
|---------|-------------|
| Access invite / PIN / suspend / revoke | Access-centre domain facts + `projectStaffAccessEntry` |
| Onboarding invite / checklist | Onboarding centre domain facts + `projectStaffOnboardingEntry` |
| Credential blockers | `projectStaffComplianceEntry` / existing status fields |
| Roster eligibility signal | `projectRosterStaffEntry` with presentation-score domainEligible; null without `staffId` |
| Overview UI fields | `toStaffProfileOverviewModel` adapter keeps existing panel/menu DTO |
| Server mutation authority | Unchanged — menu flags are presentation only |
| No parallel composition | Old hub loader no longer re-implements identity gate / audit join |
