# FI-TEAM-COHESION-B1.7 — Command Centre Identity Composition

**Status:** GREEN (2026-08-05)  
**Predecessor:** [b1.6-staff-profile-hub-proof.md](./b1.6-staff-profile-hub-proof.md)

## What landed

Workforce Command Centre is now a **many-person composition layer** over canonical identity and domain projections under `src/lib/team/commandCentre/`:

```
Load command-centre subject set (members + scheduling ids)
        ↓
Batch-resolve identities once (member batch + orphan staffId batch)
        ↓
Build domain projections in batches
        ├── directory  → projectStaffDirectoryEntry (in-memory)
        ├── access     → access centre + projectStaffAccessEntry (preresolved map)
        ├── onboarding → invite/checklist batch + projectStaffOnboardingEntry
        ├── roster     → projectRosterStaffEntry (null without staffId)
        └── compliance → credentials batch + projectStaffComplianceEntry
        ↓
Compose person summaries + TeamAttentionQueueItem[] + TeamCommandCentreKpis
        ↓
Adapter → existing WorkforceCommandCentreClient DTO
```

Legacy `workforceCommandCentrePage.server.ts` **delegates** person composition to `loadTeamCommandCentre` and adapts the existing client contract — no large UI refactor.

Profile attention contract (B1.6) is reused: each queue item retains person identity, originating domain, reason code, severity, corrective href, and action eligibility.

## Identity direction

```ts
loadTeamCommandCentre({ tenantId })
// → resolveStaffIdentities({ by: "staffMemberId", ... })
// → supplemental resolveStaffIdentities({ by: "staffId", orphanIds })
// → dedupe by personKey
```

No per-person `loadStaffProfileHub` loop.

## Partial identity behaviour

| Identity state | Command Centre behaviour |
|----------------|--------------------------|
| Linked | Normal summary |
| Scheduling-only | Visible with lifecycle / reconciliation attention; no invented onboarding/compliance |
| Lifecycle-only | Visible through onboarding / access / compliance attention; no invented roster |
| Ambiguous | Reconciliation attention; unsafe actions suppressed |
| Invalid | Visible when actionable attention exists; actions suppressed |
| Cross-tenant | Excluded from workforce totals; hard integrity attention |
| Terminated | Excluded from active / headcount totals |
| Suspended access | Employment vs access remain distinct via projections |

## Query budget

`loadTeamCommandCentre`:

1. One subject load (members select + `loadAllStaffForTenant`)
2. One identity batch (+ optional orphan staffId batch)
3. One access batch with **shared** `preresolvedIdentitiesByMemberId`
4. One onboarding invite + checklist batch
5. One credentials batch
6. In-memory roster / directory projections

No dual-table join in the Command Centre loader. No profile-loader N+1.
