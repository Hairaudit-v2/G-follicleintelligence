## Discovery (why not move into directory)

B0/B2.3a incorrectly proposed `staffHrNotification*` → `team/directory`. That is wrong:

| Concern | Evidence | Owner |
|---------|----------|-------|
| Sync staleness threshold | `STAFF_HR_SYNC_STALE_DAYS` consumed by `workforceIdentitySummary`, `workforceIdentityReadinessSignals`, `hrStaffSyncHealthDashboard` | **Identity Readiness** |
| Readiness scoring / clinical gates | `workforceReadinessEngine`, `hrStaffReadinessDashboard`, directory picker — use counts / `hasHrLink` / `isSyncStale` / onboarding status | **Identity Readiness** (contracts); directory **displays** only |
| Badge labels / variants / alerts | `StaffHrNotificationBadge`, notification summary builders | **Team Notifications** |
| Portal URL pick + source-system priority | `myHrPortalSelection`, `pickHrPortalUrl` inside summary builder | **Team Notifications** |
| Loaders | `staffHrNotificationLoader.server`, `myHrPortalLoader.server` | **Team Notifications** (server) |

Moving the whole hotspot into Directory would create **identity → directory** pressure (identity already imports the stale-day constant from the notification module today).

## Phase 1 — mix audit (must-split gate)

Legacy `src/lib/staff/staffHrNotificationSummary.ts` **mixed** (pre-delivery):

1. Readiness classification (`STAFF_HR_SYNC_STALE_DAYS`, onboarding resolve, sync-stale predicate, count aggregation, `hasHrLink`)
2. Notification composition (`variant`, `badgeLabel`, `shortLabel`, `alerts`)
3. Portal selection (`HR_PORTAL_SOURCE_SYSTEM_PRIORITY`, `isAllowedHrPortalUrl`, `pickHrPortalUrl`)
4. No direct delivery side effects (pure) — but loaders have DB/auth delivery adjacent to composition

**Gate:** Delivery proceeds only by **splitting** this file so no shipped module still mixes those concerns.

Post-split ownership:

- `team/identity/readiness/hrReadinessContracts.ts` — readiness only
- `team/notifications/myHrPortalSelection.ts` — portal selection only
- `team/notifications/staffHrNotificationSummary.ts` — notification composition (imports readiness + portal; does not redefine thresholds)

`myHrPortalSelection.ts` is already pure portal selection → notifications (no split).  
`staffHrNotificationLoader.server.ts` / `myHrPortalLoader.server.ts` are server orchestration → notifications/server (no split of readiness out of them beyond importing moved pure modules).
