## Recommended implement-next cluster — **Roster hours + clinical staffing types**

**Intended Team domain:** `team/roster`  
**Why:** Highest-fan-out pair that already has a single clear owner (roster owns standard hours and clinical staffing summary DTOs). No B3 action rename required. Pure/types-first wedge with a bounded core helper.

### Candidate files

| File | Consumers | Kind | Proposed path |

| `src/lib/workforce-os/staffStandardHoursCore.ts` | 14 | pure core | `src/lib/team/roster/staffStandardHoursCore.ts` |
| Co-located tests for standard hours (if present beside core) | — | test | co-locate under `team/roster/` |

**Optional same-slice only if inventory proves acyclic and roster-owned:** thin pure re-exports already consumed exclusively by standard-hours (none required for gate).  
**Do not include in B2.3:** `staffWeeklyHours.ts` (directory-classified but imported by roster generation — ownership decision separate), roster command-centre servers, `workforce-roster-actions` (B3).

### Inbound (who imports these)

**`clinicalStaffingSummary.types.ts`**

- UI: appointment / booking drawer / clinical staffing badges & cards
- Loaders: appointment slide-over, calendar-os booking card / warnings, clinic tomorrow board, surgery boards
- Bridges: `workforceEventAssignmentBridge.server`, calendar operational types

**`staffStandardHoursCore.ts`**

- UI: roster shift drawer, staff standard hours page
- Roster: generation core/server, manual adjustments, rostering server, roster query params, roster command centre
- Cadence: `rosterCadencePolicyCore`
- Actions: `workforce-roster-actions` (**leave actions registered; do not rename in B2.3**)

| `staffStandardHoursCore.ts` | `@/src/lib/staff/staffWeeklyHours` | **leaves a legacy edge** unless weekly-hours is also moved or roster gets a local hours contract |
