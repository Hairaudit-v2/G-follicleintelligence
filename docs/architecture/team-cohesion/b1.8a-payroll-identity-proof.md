**Status:** GREEN (2026-08-05)

## What landed

Payroll identity now resolves through `src/lib/team/payroll/`:

```
Discriminated input (staffMemberId | staffId)
        ↓
Canonical resolveStaffIdentity / resolveStaffIdentities
        ↓
projectPayrollStaffEntry (employment + readiness flags — no rates)
        ↓
Mutations: assertEligiblePayrollIdentityTarget
Shift-cost: batch by staffId for attribution keys
Page: payrollStaffEntries adapter field (UI unchanged)
```

**Canonical entity rule:** identity identifies the person; payroll records determine the money. Wage rates / payable hours remain in protected wage and timesheet DTOs.

## Identity direction

| Flow | Key |
|------|-----|
| Wage profile / timesheet mutations | `by: "staffMemberId"` (discriminated — no silent fallback) |
| Shift-cost / rostered labour | `by: "staffId"` batch |
| Auth user | Not used as payroll identity key |

## Partial identity behaviour

| State | Behaviour |
|-------|-----------|
| Linked active | Normal payroll processing |
| Scheduling-only + historical shifts | Attribution retained; `historical_attribution_only` attention; no profile edit |
| Lifecycle-only + wage setup | Setup remains visible / editable when permitted |
| Suspended login | No automatic effect on pay eligibility flags |
| Ambiguous / invalid / cross-tenant | Mutation hard rejection |
| Missing wage profile | Attention; no guessed default rate |
| Employment ended | Attention; effective-date math unchanged |

## Do-not-break register

Preserved: wage `effectiveFrom`/`effectiveTo`, hourly/daily/contractor distinctions, timesheet approval transitions, shift-cost calculations, historical attribution, tenant isolation, HR manage gates, audit metadata (`payrollIdentity` personKey + dual ids), no automatic wage creation on identity repair.
