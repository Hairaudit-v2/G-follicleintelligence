## Discovery (why not directory / identity)

Legacy inventory labelled `staffWeeklyHours` / `staffSlotHours` as directory. That is wrong:

| Concern | Evidence | Owner |
|---------|----------|-------|
| Recurring weekly template (`fi_staff.working_hours`) | Parse/serialize + window predicates used by roster engine, standard-hours sync, calendar, HR readiness display | **Team Roster Availability** |
| Effective availability for a UTC range | `getStaffAvailabilityForRange` — weekly OR `available_override`, blocked by leave/sick/etc. | **Team Roster Availability** |
| Appointment slot allow/deny | `assertStaffAppointmentWithinWorkingHours` — loads staff + currently only weekly; must compose roster effective availability + directory bookability | **Bookings** |
| Contracted / wage / timesheet hours | `fi_staff_standard_hours`, payroll — not this JSONB weekly template | **Payroll** (deferred; must not absorb into weekly) |

Directory may edit/display weekly hours in staff UI but must **not** own the contract. Identity must **not** own weekly hours or booking gates.

## Locked ownership model

1. **Team Roster Availability** owns the recurring scheduling template and effective-availability predicates for a UTC range.
2. **Explicit blocks override the template:** precedence is blocking leave/unavailable → `available_override` → weekly template (clinic/resource constraints remain outside this contract).
3. **Bookings** owns the final appointment-slot gate, composing roster effective availability + directory bookability + booking errors. Bookings must not reimplement weekly parse or block precedence.
4. **Payroll/employment** contracted hours stay separate.
5. **Same-day overrides:** existing `fi_staff_availability_blocks.available_override` (via `createAvailabilityBlock`) must immediately affect booking acceptance once the gate is wired — no rewrite of permanent weekly hours. Product UI for “mark available outside hours” remains deferred; API + tests prove behaviour this slice.
