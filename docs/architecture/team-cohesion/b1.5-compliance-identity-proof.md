# FI-TEAM-COHESION-B1.5 — Compliance and Credentials Identity Proof

**Status:** GREEN (2026-08-05)  
**Predecessor:** [b1.4-roster-identity-proof.md](./b1.4-roster-identity-proof.md)

## What landed

Credentials page aggregation (`src/lib/workforce/credentialsPage.server.ts`) now consumes:

```ts
resolveStaffIdentities({ tenantId, by: "staffMemberId", staffMemberIds })
```

plus a bounded credentials batch (`loadStaffCredentialsForMembers`) and projects via `@/src/lib/team/compliance`:

- `StaffComplianceEntry` (presentation DTO)
- Distinct credential/certification summaries from **existing** evaluated statuses
- `attentionReasons` for identity integrity + compliance blockers
- Action flags bridged onto credentials page rows

Compliance alerts page (`compliancePage.server.ts`) also batch-resolves alert subjects for names and identity attention (no raw members-name join).

Credential / certification mutations (`create` / `update` / `verify`) call `assertEligibleComplianceIdentityTarget` and record `staff_member_id`, `fi_staff_id`, and `person_key` in audit metadata.

## Behavioural rule

Lifecycle-only identities are **first-class compliance subjects**. Scheduling-only without a lifecycle id cannot receive credential mutations. Ambiguous / invalid / cross-tenant targets suppress upload/verify/reject flags and are rejected server-side. Missing auth / suspended access do not erase credential history.

Identity attention is layered beside compliance blockers — it does not replace expiry, rejection, or incomplete-certification reasons.

## Query budget

`loadCredentialsPageModel`:

1. **One** lifecycle members load
2. **One** `resolveStaffIdentities({ by: "staffMemberId" })` batch
3. **One** credentials `.in(staff_member_id)` batch

No per-person identity or credential query loop.

## Safety preserved

| Concern | Disposition |
|---------|-------------|
| Upload / storage / expiry | `evaluateCredentialExpiry` unchanged |
| Verify / reject | Certification verify gated; status evaluation unchanged |
| Audit history | Append-only audit retained; canonical ids added to metadata |
| Readiness blocker precedence | Domain blockers derived from records first; identity layered |
| HR manage permissions | Actions still call `assertWorkforceHrManageAllowed` |
| No auto-reassignment on repair | Mutations bind to resolved lifecycle id only |
| History on termination | Existing employment filters / archival behaviour untouched |
| Downstream roster / onboarding | No readiness engine rewrite in this slice |
