## Phase 2 — Delivery steps

1. **Extend CalendarOS block model** — new kinds + tones; `deriveWorkforceBlocksForStaffRow` accepts `availabilityBlocks` (+ optional staff timezone) and emits placed/full-day chrome from overlapping blocks and weekly template, labeling via `getStaffAvailabilityForRange(...).explanation` for block windows (and day-band outside/hours where useful).
2. **Loader plumbing** — load active overlapping `fi_staff_availability_blocks` for calendar staff IDs × visible range; attach `availabilityBlocksByStaffId` (or equivalent) to `OperationalCalendarPageData` + `OperationalCalendarGridPatch` so `router.refresh` / grid hydrate replaces blocks with bookings.
3. **Wire UI** — pass blocks CalendarOsShell → DayResourceView → derive.
4. **Assignment bridge parity** — extend `SchedulingConflictInput` with `workingHours` / timezone; when no overlapping blocking block and range is outside weekly hours **without** covering `available_override`, emit `outside_weekly_hours` conflict. Leave/sick/unavailable continue to emit as today. Do **not** treat override as a conflict. Call sites that already load blocks must pass working hours (bridge already has staff via `buildReadinessInputForStaff`).
5. **Soft warning** — preserve `allowBlockedDraft` behaviour: conflicts → assignment `blocked` + explicit `warnings` (leave + outside-hours). When `allowBlockedDraft` is false, hard-fail as today. No silent success when effective availability denies.
6. **Tests + architecture** — CalendarOS resource/block tests; engine conflict + effective availability; bridge/unit coverage for override-allow and leave-deny; inventory regenerator; allowlist ≤12; cycles 0; shims 0.
7. **Plan + proof** under `docs/architecture/team-cohesion/`.

## Dependency rules

**Allowed**

- CalendarOS / operational calendar loader → `@/src/lib/team/roster/availability` (client-safe)
- Assignment bridge / engine soft conflicts → roster availability
- Bookings gate remains sole hard appointment write authority

**Forbidden**

- Duplicating leave/override precedence in CalendarOS
- CalendarOS importing Bookings gate internals
- Compatibility shims · new cycles · identity allowlist growth · dual-table joins
- Editing recurring weekly hours from this slice
- New override-creation UI
