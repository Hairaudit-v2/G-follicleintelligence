## Delivered

### 1. CalendarOS leave / override lane chrome

- Extended kinds: `sick_leave`, `available_override`, `outside_hours` (+ existing leave / unavailable / working_hours).
- `deriveWorkforceBlocksForStaffRow` consumes payload `availabilityBlocks` and labels via `getStaffAvailabilityForRange(...).explanation` (no local leave/override policy).
- Weekly template still drives RDO / lunch / outside-hours bands; DB blocks overlay with canonical reasons.

### 2. Operational calendar payload plumbing

- `loadOperationalCalendarGridData` loads overlapping active `fi_staff_availability_blocks` for calendar staff × visible range.
- `availabilityBlocksByStaffId` on `OperationalCalendarPageData` / `OperationalCalendarGridPatch` (shell starts empty; grid hydrate / `router.refresh` replaces blocks with bookings).

### 3. Assignment bridge soft-conflict parity

- `detectStaffSchedulingConflicts` accepts `workingHours` / `staffTimezone`.
- Outside weekly hours without covering `available_override` → `outside_weekly_hours` conflict.
- Leave / sick / unavailable continue to conflict; override does **not** get conflicted for outside hours.
- Bridge / roster / command-centre / manual-adjustment callers pass working hours.
- With `allowBlockedDraft` (default), conflicts surface as explicit `warnings` + `blocked` assignment — not silent success. Bookings gate remains hard authority for appointment writes.
