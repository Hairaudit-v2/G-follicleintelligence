## 1. Core one-sentence positioning

> Follicle Intelligence is the purpose-built operating system for modern hair restoration clinics — connecting patient acquisition, clinical decision-making, surgery, imaging, outcomes, workforce and business performance in one longitudinal record.

---

## 2. Transition / adoption message

> Clinics can connect their existing systems, transition in controlled stages, or progressively move their operations into Follicle Intelligence.

**Clinic-owner simplification:**

> Connect, transition or replace — at a pace that protects clinic continuity.

## 3. Short platform description (shared)

Follicle Intelligence is a vertical operating system for hair restoration — not a generic clinic CRM and not a loose bundle of point tools. Lead management, consultations, surgery, imaging, outcomes, workforce and commercial performance sit on one connected patient history so clinics can operate with fewer disconnected systems and clearer accountability.

---

## 4. Clinic-owner description

Hair restoration clinics typically run on systems that were never designed to work together. Enquiries live in one place, surgery planning in another, imaging and outcomes elsewhere, and staff memory fills the gaps.

Follicle Intelligence connects that journey in one purpose-built operating system: better enquiry follow-up, clearer ownership, safer preparation for surgery, one patient history, and better visibility of outcomes — with the option to adopt progressively so day-to-day clinic work is not disrupted.

**Priorities to emphasise for clinic owners**

- Fewer disconnected systems  
- Better enquiry follow-up  
- Clearer accountability  
- Safer, staged migration  
- One patient history  
- Better surgery preparation  
- Better visibility of outcomes  
- Reduced reliance on spreadsheets and staff memory  
- Operational continuity  
- Progressive adoption  

---

## 5. Investor / strategic partner description

Hair restoration is a growing global medical sector still running on fragmented software. Follicle Intelligence is building vertical infrastructure for the category: deep workflow across commercial, clinical, surgical and outcome layers; structured longitudinal data; and a repeatable path for clinics to move from connected systems into a primary operating system.

As commercial, clinical, surgical and outcome history remains connected, the platform becomes increasingly valuable to the clinic over time — supporting multi-site standardisation, higher switching costs once operationally embedded, and a long-term intelligence network built on structured specialty data.

**Priorities to emphasise for investors and partners**

- Vertical software defensibility (expressed without jargon on clinic pages)  
- Structured longitudinal data  
- Workflow depth  
- High switching costs once operationally embedded  
- Cross-module intelligence  
- Expanding data advantage over time  
- Repeatable migration pathway  
- Multi-site potential  
- Commercial and clinical network effects  
- Transition from software product toward industry infrastructure  

**Do not paste investor jargon onto clinic-facing pages.** Prefer plain operational language that still signals maturity.

| Avoid (investor-only tone on clinic pages) | Prefer publicly |
| --- | --- |
| “Defensibility through workflow lock-in and a proprietary data moat.” | “Because the patient’s commercial, clinical, surgical and outcome history remains connected, the platform becomes increasingly valuable to the clinic over time.” |
| “Our TAM is supported by vertical SaaS consolidation.” | “Hair restoration clinics currently rely on multiple systems that were not designed to work together. FI replaces that fragmentation with one purpose-built operating system.” |

## 6. What the website must communicate

1. FI is larger than a CRM.  
2. CRM and lead management are one operational layer within FI (LeadFlow).  
3. FI is purpose-built for hair restoration, not adapted from horizontal software.  
4. FI connects commercial activity with clinical, surgical and outcome intelligence.  
5. FI can support controlled migration from HubSpot.  
6. Migration is staged, auditable and designed to protect patient identity and operational continuity.  
7. The platform is entering operational use; unfinished capabilities must not be presented as fully deployed.  
8. The long-term intelligence network and structured dataset remain part of the strategic vision — framed as vision, not as completed product.

## 9. HubSpot relationship model

Public wording must distinguish four relationships. Do not collapse HubSpot into “just an integration.”

| Mode | Definition |
| --- | --- |
| **Connect** | Selected data or workflows continue to operate with HubSpot connected to FI. |
| **Coexist** | FI and HubSpot operate alongside one another during a controlled adoption period. |
| **Transition** | Selected contacts, leads, history and workflows move into FI in verified stages. |
| **Replace** | FI becomes the primary system for CRM and clinic operations within the agreed deployment scope. |

### Clinic-owner simplified line

> Connect, transition or replace — at a pace that protects clinic continuity.

(Coexist is implied by “connect” and progressive transition; use the full four modes on enterprise, progress and dedicated migration pages.)

### Safe public migration proof points

Allowed when accurate:

- Historical backup before migration  
- Preview before application  
- Staged migration cohorts  
- Identity reconciliation  
- Duplicate prevention  
- Patient-record protection  
- Post-migration verification  
- Auditable migration history  
- Controlled rollback boundaries (only where accurate)  
- Continued operation during staged transition  

### Never publish

- Batch UUIDs  
- Checksums  
- Database table names  
- Internal scripts  
- Tenant identifiers  
- Security implementation details  
- Patient information  
- Migration cohort identities  
- Internal gate names  

### Approved HubSpot migration paragraphs

**Clinic-facing**

> If your clinic uses HubSpot today, you do not need an all-or-nothing cutover. Follicle Intelligence can connect to HubSpot, run alongside it, transition selected contacts and history in verified stages, or become the primary system for CRM and clinic operations when you are ready. Migration is designed to protect patient identity, prevent duplicates, and keep operations running during the transition.

**Investor / partner-facing**

> FI includes a controlled HubSpot migration capability: staged cohorts, identity reconciliation, duplicate prevention, preview before application, and auditable history. That pathway reduces adoption risk for clinics and creates a repeatable route from horizontal CRM into a vertical operating system.

**Short CTA support line**

> Move from HubSpot to Follicle Intelligence in controlled stages — with preview, verification and continuity built into the process.

## 10. Platform status model (public)

Replace ambiguous completion percentages with these categories unless a single maintainable calculation is later approved and documented.

| Status | Definition |
| --- | --- |
| **Deployed** | Available for routine operational use within the approved deployment scope. |
| **Operational Pilot** | Live in controlled clinical or operational use, with continued validation and expansion. |
| **Advanced Build** | Core workflows exist and are undergoing integration, testing or deployment preparation. |
| **In Development** | Actively being designed or implemented but not ready for operational claims. |
| **Research and Future Development** | Strategic intelligence, network or research capabilities that are not yet operational products. |

### Mapping from current internal progress labels (guidance for 1B)

| Current registry language | Prefer public status |
| --- | --- |
| Live / Production / Infrastructure Complete (when genuinely in routine use) | Deployed |
| Operational beta / Pilot Ready (when in controlled live use) | Operational Pilot |
| Active Development with substantial shipped workflows / “Advanced Build” labels | Advanced Build |
| Early Active Development / incomplete core path | In Development |
| Intelligence network vision, future models, global accreditation network claims without productisation | Research and Future Development |

### Percentage policy

**Recommendation: Option B — remove public completion percentages in favour of the status model above.**

Rationale (see messaging inventory):

- `FI_ECOSYSTEM_COMPLETION_SUMMARY` uses manual figures (`overallEcosystemPercent: 78`, `fiOsCorePlatformPercent: 77`).  
- Homepage hero currently shows **81% Platform Deployment** (`HOME_V5_CONTENT`).  
- Progress metrics card shows **77% Ecosystem Completion**.  
- Module-level percentages are manually edited and not a single maintainable calculation.  
- Public averages and hero metrics therefore conflict and are not investor-defensible.

Until percentages are removed:

- Do not invent new percentage claims.  
- Do not present unfinished modules as Deployed.  
- Prefer status badges over headline completion %.

## 11. Claims and evidence rules

| Rule | Application |
| --- | --- |
| Prefer evidence over superlatives | “Operational pilot,” “staged migration,” “structured capture” over “world’s first” |
| Separate vision from product | Network / dataset scale language must be clearly future-facing |
| Module status honesty | Never imply every listed module is Deployed |
| CRM framing | FI is an OS; LeadFlow is the CRM/acquisition layer |
| Migration honesty | Staged and controlled — never “instant” or “zero risk” |
| Quantification | Only publish numbers that are documented, current, and consistent across the user journey |
| “World’s first / largest” | Discouraged on public pages; if used at all, max once site-wide and only with legal/marketing approval |

### Module-count consistency

Do not mix competing counts on adjacent journeys without explanation.

| Pattern | Guidance |
| --- | --- |
| “Eight core systems” | Acceptable for a curated homepage subset if linked to full architecture |
| “Twelve intelligence layers” | Acceptable for ecosystem architecture narrative |
| “20 interconnected systems” | Acceptable only on progress/architecture pages that enumerate them |
| “Thirteen OS modules” | Align or retire; do not use beside conflicting counts without a footnote |

When in doubt: **“One operating system with connected operational layers”** plus a named subset.

## 13. Prohibited or discouraged wording

### Prohibited

- Calling Follicle Intelligence “just a CRM”  
- Exposing internal migration artefacts (UUIDs, table names, gates, tenant IDs, checksums, scripts)  
- Patient data or identifiable migration cohort details  
- Claiming all modules are fully deployed  
- “No risk,” “zero downtime guaranteed,” “instant migration”  
- Presenting Research and Future Development as Deployed  

### Discouraged

- Repeated “world’s first” / “world’s largest”  
- LeadFlowOS / LeadFlow OS  
- Generic SaaS filler (“revolutionise,” “seamless,” “next-gen,” “AI-powered” without substance)  
- “No operational disruption” as an absolute (prefer “designed to protect continuity”)  
- Competing completion percentages across pages  
- HubSpot framed only as a connector logo
