# FI-PATIENT-APP-2B — Usability test plan

**Status:** Plan approved for execution — **sessions not executed** (results must not be invented).

## Rating scales (exact)

| Metric | Scale |
| --- | --- |
| Task success | Success unassisted / Success assisted / Fail |
| Confidence | 1–5 (1=not confident, 5=very confident) |
| Ease of use (patient) | 1–5 (1=very difficult, 5=very easy) |
| Usefulness (clinic staff) | 1–5 (1=not useful, 5=very useful) |
| Agreed medians for gate | Patient ease ≥ **4**; clinic usefulness ≥ **4** |

## Severity

Critical / High / Medium / Low — definitions per FI-PATIENT-APP-2B brief.

## Gates

- 100% success identifying next action
- 100% success locating Help
- 100% understanding app is not for emergencies
- ≥90% unassisted success across core Phase 1 tasks
- No unresolved Critical
- No unresolved High affecting pilot pathway
- Medians meet thresholds above

## Minimum participants

- 3–5 non-engineering internal
- 2–3 clinic staff
- 3–5 controlled demonstration participants
- Prefer ≥10 completed sessions total

## Required tasks (1–15)

Welcome/pilot context; next action; Action Centre; open action; complete/acknowledge; return unfinished; Journey Timeline; milestones; quote; document; pathology; notification destination; Help; emergency disclaimer; log out.

## Capture for each session

Participant id (non-PII), role, device, task outcomes, time on task, assistance, navigation errors, misclicks, comprehension errors, ratings, support requests, qualitative comments, issues logged with severity.

## Issue / retest log

Maintain in protected ops storage; summary of open Critical/High may be mirrored without PII after execution.
